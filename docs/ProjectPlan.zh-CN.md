## 2. 仓库与技术结构

音乐仓库由已建的 `NextKde/nextkdeMusic` 改名为 `NextKde/KMusic`，组件 Gallery
仍在 `NextKde/nextkdeAppDemo`。改名和本地目录/remote/自动任务路径一起调整，保留已有历史。

界面保持 Qt Quick/QML；业务、数据库、播放控制与音源适配分层。Kos.Ui 通过 Git 子模块固定版本，
并由 KMusic 的 CMake 直接 add_subdirectory 该子模块的 shared/qml，链接 Kos::Ui / Kos::UiPlugin，
QML 页面实际 import Kos.Ui。建立“Git 版本引用 + 构建依赖 + 页面实例”的完整关系；禁止依靠系统上
另一份同名组件或在 App 内复制组件蒙混通过。当前只有前一层 Git 关联已准备，构建接线尚未完成。
现有 NextKde 播放后端只作为可复用基础，保留来源；不把现有 LX 音源当成用户指定的 SPlayer 音源。
在线来源使用统一 Provider 接口，UI 不直接携带请求签名、Cookie 或长期播放 URL。

建议先提取/适配 SPlayer 的音源请求模块，通过随应用启动和退出的轻量进程与 Qt 通信；
不嵌入整个 Electron/Vue 应用。第 0 阶段先确认模块对 Electron 的实际依赖、部署方式和可维护性，
再定具体桥接方案，避免大规模改写请求与加密逻辑。复用代码固定上游提交、保留作者及许可，
需要时同步调整 KMusic 许可声明。

研究基线：SPlayer-Next `05a4e5929030df21a8448ddb24c77dbd353f974e`。
已阅读网易云 song_url、前端地址解析分类、服务器播放会话和流媒体说明。
其播放结果区分完整 URL、试听片段、无可用 URL、账号失效；这些必须成为 KMusic 的可见状态。

## 3. 首版范围

首版优先打通网易云在线音乐与本地音乐，不把示例推荐页当作在线音乐能力。

- 在线搜索歌曲/歌手/专辑/歌单，浏览歌曲与专辑/歌单详情，获取封面和歌词。
- 解析真实播放地址，实际播放/暂停/切歌/拖动进度/调节音量；处理音质选择、加载、超时、
  URL 失效、无权限、仅试听、网络错误。需要登录的能力提供账号入口，实际登录由用户完成。
- 队列、随机/循环、收藏/本地歌单、最近播放及重启后的必要持久化。
- 本地音乐导入、检索、播放，以及可用歌词的正在播放页面。
- 发现页采用清晰的精选区、专辑架和歌曲区。有真实接口时展示真实数据；
  必要的离线视觉样例明确标注，不能冒充可播放内容。
- 浅色、深色、键盘焦点、空态/错误态、窄窗与正常窗口、右侧窗控。

Subsonic/Navidrome/Jellyfin/Emby 多服务器、下载管理、标签编辑、频谱、跨设备同步
放在后续扩展，不作为首版默认承诺。首版不接入 Apple Music 账号或 DRM 播放。

## 5. 本机测试与每轮截图上传

按用户本次授权，在本机使用独立 KMusic 和 Gallery 窗口测试与截图；不替换或重启桌面 Shell、
不改 KWin、不干扰其他长期任务。截图捕获指定应用窗口，保持文字清晰，保留原始分辨率。
以 1280×800 为主，同时检查约 1024×640 与 1440×900、浅色/深色、当前桌面缩放。

自动接续间隔由 30 分钟改为 **5 分钟**。每次实际执行的轮询均执行：

1. 读短检查点，核对唯一开发者与当前版本，避免重复派发或并发覆盖。
2. 截取本轮 KMusic 和 Gallery 的新画面；开发者仍忙时也截图当前可运行版本。
   有组件改动时 Gallery 展示该控件与相关状态；动态改动另补连续帧。
3. 总验收者亲自看图及核对可执行的交互，形成少量明确差异或通过记录。
4. Gallery 图上传 `NextKde/nextkdeAppDemo`，KMusic 图上传 `NextKde/KMusic`。
   两库均使用 `ui-evidence` 证据分支；应用源码与组件源码的提交分别管理。
   每轮路径 `screenshots/round-日期时间/`，附索引、应用/组件提交、未提交改动标识、
   系统/Qt/渲染后端、窗口尺寸/缩放/主题、差异和两库链接。
5. 确认两库远端上传成功，保存检查点，再派发下一小轮；只在有意义进展或失败时通知用户。

另外，每 **15 分钟**发布一次当前源码进度并附最新截图，不必等待整个阶段完成。
同一个五分钟自动任务按 last_source_push_at 判断是否到期，避免再创建一个互相竞争的开发任务。
KMusic 源码进度推到 `codex/music-development`，共享组件源码改动推到组件仓库的
`codex/music-fidelity`；无源码变化时仍上传本轮截图和进度记录。两库 `ui-evidence` 的最新索引
链接到精确源码提交及当轮截图，默认 README 提供固定“查看最新进度”入口。
进度记录列出已完成、正在做、阻塞、构建/功能/UI 实际状态；未完成或未验收的代码明确标注。
用户可以只通过 GitHub 远程查看代码和图片。只有实际远端成功才记录为已推送；失败后保留待传项。
本机或 Codex 未运行时不能承诺定时任务持续执行，恢复后首先补齐待传进度。

不能用旧图冒充本轮截图。窗口未能启动、截图失败或上传失败时如实记录具体失败，
先修复可解决的问题；尚无可运行窗口的初始准备轮也不能声称已完成双库图像上传。
不会上传账号凭据、Cookie、私密日志或无关桌面内容。
