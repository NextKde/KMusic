# NextKde Music 设计契约

> 2026-10-20：已暂停等待用户确认新版[项目计划书](ProjectPlan.zh-CN.md)。
> 新计划覆盖本文中的 VM-only、本地音乐优先、证据目录与仓库命名约定。

[English](Design.md)

Apple Music 的“新发现”页面决定导航、编辑推荐区、专辑横排、歌曲列表与常驻播放器的信息架构。
本地 Forma `source-5bdb550` 决定控件的形状、颜色、字号、间距、材质及交互细节。
真正使用的组件来自 `NextKde/nextkdeAppDemo`，通过 Git 子模块固定版本；通用组件问题回归该仓库。
窗口骨架参考 `kos-settings`：外框直角、30px 顶部拖拽区、右侧最小化/最大化/关闭。
外框无圆角不意味着所有控件方形，内部控件仍按 Forma 的细节设计。

由协调聊天负责设计和独立验收，一个开发子 agent 负责实现。每轮派发少量明确差异，完成后再审阅。
基准窗口 1280×800，兼顾 1024×640 与 1440×900。约 240px 侧栏组织搜索、新发现、资料库与歌单；
主区包含推荐、专辑与歌曲，播放器常驻，支持详情、队列、正在播放/歌词。

首个里程碑为可用的本地音乐播放器；推荐页可使用明确标注的原创离线示例数据。
导入、搜索、播放暂停、上下曲、进度、音量、队列与歌单需有真实逻辑。可复用已有 NextKde 音乐后端，保留来源。
当前不包含 Apple Music 登录及商业曲库播放。

维护 App 使用点、共享 QML 文件及 Forma 参考的对应清单，逐项记录差异、修复版本和验收状态。
浅色/深色分别检查普通、悬停、按下、焦点、禁用、弹出与滚动状态。透明材质不降低文字透明度；
应用内采样不能冒充桌面模糊，不因该应用修改 KWin。

构建、运行、测试及图形验收全部只在虚拟机。本机只允许源码阅读、编辑和 Git 操作。
验收者亲自看实际截图，动态效果需连续帧及交互证据；记录应用与组件提交、环境、尺寸、缩放和缺口。
证据放在忽略的 `.task/acceptance/`，构建通过不能当作 UI 验收通过。
交付前覆盖所有主要页面、本地播放流程、持久化、空态/错误态、键盘、窗控及不同主题/尺寸；
组件修复同时回归 nextkdeAppDemo 的相关使用点。
